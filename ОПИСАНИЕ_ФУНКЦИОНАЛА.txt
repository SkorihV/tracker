============================================================
TIME TRACKER v2 — ОПИСАНИЕ ФУНКЦИОНАЛА
============================================================

Программа:   desktop-приложение на Tauri 2
Бэкенд:      Rust (crate «tracker_core» + команды Tauri)
Фронтенд:    Vue 3 + Vuetify 4 (Pinia)
Сборка:      npm run build -> src-tauri (cargo tauri build)
Запуск:      tauri dev / собранный exe

Данные:
  - Файл БД:  <AppData>/data/time_tracker_v2_data.json (utf-8).
    В dev-режиме база берётся из папки, заданной переменной
    TT_BASE_DIR. Точный путь показывается в Настройках →
    «Папка с базой данных» и открывается кнопкой «Открыть в проводнике».
  - Бэкапы:   <AppData>/backups/ (либо пользовательский каталог,
    задаётся в Настройках).
  - Отчёты:   <AppData>/reports/ (по умолчанию; при сохранении из окна
    «Отчёт»/«Статистика» путь выбирается диалогом).
  - Адреса на разных ОС разные, поэтому папка БД и папка бэкапов
    показываются в настройках (только чтение).

Приложение — тайм-трекер для документооборота/логистики. Разрешены
несколько одновременно идущих задач (параллельные таймеры):
обновление списка происходит каждую секунду.


------------------------------------------------------------
1. СТАТУСЫ ЗАДАЧ И ИХ ЛОГИКА
------------------------------------------------------------
У каждой задачи есть рабочий статус (mode), один из трёх:

  running   — «Запущена», время идёт. Колонка «Режим»: зелёный чип.
  paused    — «На паузе», время заморожено. Оранжевый чип.
  completed — «Завершена», время зафиксировано. Серо-синий чип.

Хранение времени:
  - Внутри задача хранит список диапазонов работы intervals
    [{ start, stop }]. Поле seconds всегда равно сумме ЗАКРЫТЫХ диапазонов.
  - Пока задача running, к seconds прибавляется текущий открытый диапазон
    (разница «текущее время − start диапазона»).
  - Пауза/завершение закрывают открытый диапазон и прибавляют его
    длительность к seconds. Возобновление открывает новый диапазон,
    seconds НЕ сбрасывается.
  - отображается время в формате ЧЧ:ММ:СС (поле seconds — число).
  - Даты и время в редакторе, окне диапазонов и в хранении используют
    формат «дд.мм.гггг чч:мм». Старые ISO-файлы загружаются
    и автоматически сохраняются в новом формате.

ID задачи — автогенерация: ГГГГММДД-NNN-ХХХХ, например 20260920-001-a3f9.
  - NNN — порядковый счётчик за текущий день (восстанавливается по
    существующим ID при загрузке);
  - ХХХХ — 4 hex-символа md5 от ключа, чтобы ID был уникальным.

Дополнительно у задачи может быть «пользовательский статус» (status) —
значение из справочника статусов (см. раздел 5). Он отображается
в колонке «Статус» цветной ячейкой и никак не влияет на время.
Рабочий статус задачи показывается в колонке «Режим».


------------------------------------------------------------
2. ГЛАВНОЕ ОКНО
------------------------------------------------------------

2.1. Шапка
  - Выпадающий список «Группировка»: Нет / По дням / По клиентам.
  - Поле «Поиск (ID, заявка, комментарий…)» — мгновенно (по Enter
    или крестику) фильтрует по тексту без учёта регистра по полям:
    ID, номерам заявок, тегам, клиенту, пользователю, комментарию.
    Escape внутри поля — очистить поиск.
  - Кнопка «Новая задача» — создаёт задачу и открывает редактор
    (см. раздел 3). Если в настройках не задан текущий пользователь —
    открываются «Настройки».
  - Кнопка «Настройки».

2.2. Панель фильтров (над таблицей)
  - «С» / «По» — период по дате НАЧАЛА задачи (по умолчанию обе даты =
    сегодня). Поле — календарь: дата вводится вручную в формате
    дд.мм.гггг или выбирается из выпадающего календаря; применённое
    значение показывается в том же формате. Смена даты применяет фильтр
    сразу; крестик («X») возвращает сегодняшнюю дату, а не очищает поле.
  - «Пользователь», «Теги» (несколько), «Клиент» — выпадающие списки;
    выбор применяется сразу.
  - «Сбросить» — вернуть период «сегодня–сегодня» и очистить
    пользователя/теги/клиента/поиск. Кнопка «Очистить даты» отсутствует:
    сброс дат устанавливает текущую дату, а не очищает её.
  - Все фильтры работают совместно. Списки фильтров автоматически
    обновляются при изменении справочников.

2.3. Таблица
  Колонки (по умолчанию; порядок и видимость настраиваются):
    Время | Статус | Наша машина | Действия | Режим | Заявка | Клиент |
    Тег | Начало | Завершение | Пользователь | Комментарий | (ID скрыта).
  Ширина колонок подстраивается под содержимое; колонки «Заявка»,
  «Комментарий», «Клиент» и «Тег» можно изменить мышкой: навести курсор
  на правый край заголовка (появится подсветка), зажать ЛКМ и тянуть.
  Минимальная ширина — 50px; у колонки «Комментарий» есть максимальная
  ширина 500px — ресайз упирается в неё. Двойной клик по подсвеченному
  краю возвращает ширину по умолчанию. Ширины запоминаются между
  запусками приложения.
  Строки отсортированы по дате начала (новые сверху).

  Ячейки:
  - «Время» — накопленное время (у running-задач «тикает» в реальном
    времени, т.к. список обновляется каждую секунду).
  - «Статус» — цветная ячейка настроенного статуса + выпадающий список
    для быстрой смены статуса.
  - «Наша машина» — ячейка, залитая цветом «Наша машина» из настроек,
    если у задачи включён флаг.
  - «Режим» — чип: «Запущена» / «На паузе» / «Завершена».
  - «Действия» — кнопки по статусу:
      running   → Пауза | Завершить
      paused    → Возобновить | (Завершить заблокировано)
      completed → Возобновить
    Плюс всегда: «Редактировать», «Удалить».

  - «Пауза»       — закрыть текущий диапазон, время зафиксировано, задача paused.
  - «Завершить»   — закрыть диапазон, задача completed.
  - «Возобновить» — открыть новый диапазон сейчас (работает из paused
    и completed), задача running.

  Выделение и удаление:
  - Клик по строке — выделение/снятие; Shift+клик — диапазон;
    чекбоксы в первой колонке и в шапке («выбрать все»).
  - Выбранные строки подсвечиваются.
  - Кнопка «Удалить выбранное (N)» появляется в нижней панели;
    подтверждение — отдельное окно. Удалить можно и кнопкой в колонке
    «Действия».
  - Двойной клик по строке — открыть редактор задачи.
  - Клики по элементам управления (инпуты, кнопки, меню) выделение не
    переключают.

  Группировка:
  - «По дням» — группы-заголовки «01.01.2026 (N, ЧЧ:ММ:СС)».
  - «По клиентам» — группы по имени клиента, пустой клиент → «(не указан)».
  - «Нет» — обычный список.
  Строки-заголовки не выделяются, не редактируются и не удаляются.

  Строка итогов под таблицей: «Задачи: N | Общее время: ЧЧ:ММ:СС».
  Кнопки: «Отчёт», «Статистика», «Экспорт/Импорт».
  Если записи отсутствуют — сообщение «Нет данных».

2.4. Горячие клавиши (главное окно)
  - Ctrl+N — новая задача;
  - Ctrl+F — фокус в поле поиска (текст выделяется);
  - Delete / Backspace — удалить выделенное (с подтверждением);
  - Escape в поле поиска — очистить поиск.

2.5. Модальные окна
  - Все окна (Настройки, Отчёт, Статистика, Экспорт/Импорт, редактор
    задачи) — модальные. Окно «Новая задача»/редактор задачи — persistent:
    НЕ закрывается кликом вне окна и клавишей Esc (закрытие — только
    кнопками «Отмена»/крестик/«Сохранить»).
  - У остальных окон закрытие крестиком/кнопкой «Закрыть»/Esc закрывает
    окно без сохранения.


------------------------------------------------------------
3. РЕДАКТОР ЗАДАЧИ (модальное окно)
------------------------------------------------------------
Открывается по двойному клику на строке, кнопке «Редактировать»
в колонке «Действия» или сразу после «Новая задача».

Поля:
  - Пользователь — выпадающий список с фильтрацией при вводе.
  - Номера заявок — редактор списка (см. ниже).
  - Теги — несколько тегов (чипы) из справочника.
  - Клиент — комбо-поле: можно выбрать из справочника или ввести новый.
  - Статус — выпадающий список из справочника статусов + цветной кружок
    предпросмотра.
  - «Наша машина» — флажок.
  - Начало / Завершение — поля формата «дд.мм.гггг чч:мм» с маской ввода.
    Завершение может быть пустым. Некорректный формат игнорируется
    (значение не меняется).
  - Если в задаче несколько диапазонов, появляется кнопка
    «Редактировать временные диапазоны» — окно со строками
    «дд.мм.гггг чч:мм — дд.мм.гггг чч:мм» (завершение можно оставить
    пустым). Поддерживаются Копировать/Вставить (Ctrl+C/Ctrl+V) и
    Ctrl+A. Неверная строка отклоняется с сообщением; диапазон должен
    быть хотя бы один. После сохранения диапазонов поля «Начало»/
    «Завершение» обновляются по последнему диапазону.
  - Комментарий — многострочное поле.

Редактор номеров заявок:
  - Поле ввода + Enter, «+» или «Сохранить» — добавить номер(а) в список.
    Введённая строка разбивается по запятым и пробелам: «123, 456 789»
    добавит три номера; дубликаты игнорируются.
  - Карандаш — inline-редактирование строки: Enter — применить,
    Esc или клик вне поля — отменить (изменения не сохраняются).
    Кнопка с галочкой активна и подсвечена цветом из настроек, только
    если значение отличается от исходного (иначе — отключена).
  - Корзина — удалить номер; «Удалить все» — с подтверждением.

Поведение окна:
  - «Сохранить» — применяет изменения: сохраняет поля, даты (если
    корректны и отличаются), диапазоны (если редактировались) и закрывает.
  - «Отмена» / крестик — закрыть БЕЗ сохранения.
  - Клик вне окна / Esc — окно не закрывается (persistent).


------------------------------------------------------------
4. ОТЧЁТ
------------------------------------------------------------
Окно «Отчёт»: период («Дата с»/«Дата по» — календарь, пустое значение =
без ограничения), формат файла (XLSX | TXT | MD | CSV), предпросмотр.

Предпросмотр формируется автоматически при изменении периода/поиска:
  - количество записей, общее время, разбивка по тегам;
  - таблица по видимым колонкам главного окна (без «Действия»).

Кнопка «Сохранить (.EXT)» — диалог сохранения файла (по умолчанию
report_<ГГГГММДД_ЧЧММСС>.ext), путь сохраняется и показывается.

  - TXT  — период, количество, общее время, разбивка по тегам,
    детализация с комментариями и столбцом «Диапазоны» (все интервалы).
  - MD   — то же в виде Markdown-таблиц.
  - CSV  — кодировка cp1251 (корректно открывается в Excel), шапка:
    Дата начала | Дата окончания | Пользователь | Номера заявок |
    Клиент | Теги | Время (чч:мм:сс) | Комментарий | Диапазоны.
  - XLSX — книга Excel с цветной шапкой (цвет = акцентный из настроек):
    «ОТЧЁТ ПО ВРЕМЕНИ», период, «Записей», «Общее время», «По тегам»
    и детализация по выбранным колонкам.


------------------------------------------------------------
5. СТАТИСТИКА
------------------------------------------------------------
Окно «Статистика»: период и формат — как в «Отчёте». Предпросмотр
формируется автоматически.

Общие показатели:
  - количество записей;
  - общее время;
  - среднее время на задачу.

Разбивки (таблицы «Имя | Задач | Общее время | Среднее»):
  - по пользователям;
  - по клиентам;
  - по тегам;
  - по месяцам (всегда; полезна при больших периодах).
Строки сортируются по убыванию общего времени; пустые группы не
показываются.

Кнопка «Экспорт (.EXT)» — диалог сохранения файла
(stats_<ГГГГММДД_ЧЧММСС>.ext): TXT, MD, CSV (cp1251) или XLSX
(акцентная шапка, общие показатели + разделы по пользователям/
клиентам/тегам/месяцам).


------------------------------------------------------------
6. ЭКСПОРТ / ИМПОРТ (JSON)
------------------------------------------------------------
Две вкладки; в каждой — галочки выбора данных: Задачи, Теги, Клиенты,
Пользователи, Статусы (все включены по умолчанию).

Вкладка «Экспорт»:
  - поле имени файла по умолчанию (time_tracker_export.json);
  - кнопка «Экспорт» — диалог сохранения; в файл попадают только
    выбранные разделы (настройки попадают всегда).

Вкладка «Импорт»:
  - выбор файла (кнопка «Выбрать», крестик сбрасывает);
  - кнопка «Импортировать» — слияние (не перезаписывает, а дополняет):
    • пользователи/теги/клиенты/статусы добавляются, только если имени нет;
    • задачи добавляются, только если ID ещё не существует;
      импортированные задачи помечаются завершёнными;
    • текущий пользователь из файла подставляется, только если сейчас
      не выбран.
  - Результат («Импортировано из: …») или сообщение об ошибке.


------------------------------------------------------------
7. НАСТРОЙКИ
------------------------------------------------------------
Вкладки: Общее | Пользователи | Теги | Клиенты | Статусы |
Заголовки таблицы.

7.1. «Общее»
  - Цвет кнопок и заголовков (акцентный): палитра + поле hex + «По умолчанию».
    Применяется на кнопки («Новая задача», выделение, чипы и т.п.).
  - Цвет ячейки «Наша машина»: палитра + hex + «По умолчанию».
  - Шрифт таблицы задач: семейство + размер, «По умолчанию»; показывается
    образец. Хранится на клиенте (cookie), данные не трогаются.
  - Тема оформления: «Тёмная»/«Светлая» (cookie).
  - «Папка бэкапов»: фактический путь (только чтение), кнопка «Выбрать»
    (диалог), «По умолчанию» (вернуть стандартную папку), «Открыть в
    проводнике».
  - «Папка с базой данных»: путь (только чтение — на разных ОС разный),
    кнопка «Открыть в проводнике».

7.2. «Пользователи»
  - Выпадающий список «Текущий пользователь (для новых задач)».
  - Список пользователей: добавление (поле + «Добавить», Enter — то же),
    inline-редактирование (карандаш), удаление (с подтверждением),
    управление порядком (вверх/вниз), «Удалить все».
  - Задачи автоматически регистрируют упомянутых в них пользователей
    в справочнике.

7.3. «Теги» / «Клиенты»
  - Как «Пользователи», но элементы хранятся с авто-ID (растёт с каждым
    новым). Переименование каскадно правит значения во всех задачах;
    удаление убирает тег из справочника, в задачах название тега
    сохраняется текстом (задачи хранят название, а не ID).

7.4. «Статусы»
  - Добавление: имя + цвет (палитра). Редактирование имени (карандаш),
    цвет ячейки (палитра с предпросмотром), порядок, удаление, «Удалить все».
  - Переименование обновляет статус во всех задачах; удаление/очистка
    сбрасывает статус задач.

7.5. «Заголовки таблицы»
  - Список колонок: флажок видимости, порядок стрелками «вверх»/«вниз»,
    кнопка «По умолчанию» (вернуть порядок по умолчанию, видимость
    сохраняется). Изменения сохраняются на диск сразу.

Общее поведение редактирования списков:
  - Карандаш → фокус в поле ввода; Enter — сохранить, Esc — отмена.
  - Клик вне поля редактирования = отмена: изменения НЕ сохраняются.
  - Кнопка с галочкой «Сохранить»: активна и залита акцентным цветом
    из настроек, только если введённое значение отличается от исходного;
    иначе — отключена.
  - Дубликаты при добавлении не создаются (совпадение игнорируется).


------------------------------------------------------------
8. ХРАНЕНИЕ И ЦЕЛОСТНОСТЬ ДАННЫХ
------------------------------------------------------------
Файл: <AppData>/data/time_tracker_v2_data.json (utf-8), структура:
  - settings: username, grouping ("none"|"day"|"client"), accent_color,
    our_car_color, columns [{key, visible}], backup_dir;
  - users: список имён (строки);
  - tags / clients: [{ id, name }] (авто-ID);
  - statuses: [{ id, name, color }];
  - tasks: список задач.

Структура задачи в файле:
  - task_id, user, orders (список), order (все номера через запятую —
    для совместимости), tags (список), tag (первый тег), client,
    status (рабочий статус: running|paused|completed), custom_status
    (пользовательский статус), comment, our_car, seconds (накопленное
    время), intervals [{ start, stop }], start (первый диапазон), end
    (последнее завершение).
  - Загрузка «ленивая» (как в Python-версии): неверные записи пропускаются;
    старый формат (одиночные поля order/tag, верхнеуровневые start/end)
    поддерживается и автоматически сохраняется в новом.

  - Даты в JSON хранятся в формате «дд.мм.гггг чч:мм».
  - При повреждении/несовместимости файла он переименовывается в
    time_tracker_v2_data.json.corrupt.bak (в той же папке data/) —
    приложение стартует с пустой базой.
  - При первом запуске данные переносятся из прежней локации
    (папка data/ или файл рядом с exe).

Автобэкапы при запуске — в папке бэкапов (по умолчанию <AppData>/backups/):
  - daily_<ГГГГММДД>.json   — один на день, хранятся 7 последних;
  - weekly_<ГГГГММДД>.json  — один на неделю (ключ = дата понедельника),
    хранятся 4; если за неделю уже есть — не создаётся;
  - monthly_<ГГГГММ>.json   — один на месяц, хранятся 3;
    если за месяц уже есть — не создаётся.
  Ротация: при превышении лимита самая старая копия категории удаляется.
  Первый запуск без файла данных бэкапы не создаёт. Старые backup_*.json
  из папки data/ автоматически удаляются при запуске.

Запись: любая операция (добавление/изменение/удаление задач, справочников,
настроек, порядка колонок) сразу сохраняется в файл.


------------------------------------------------------------
9. ПРОЧИЕ ПРИМЕЧАНИЯ
------------------------------------------------------------
  - Счётчики ID задач восстанавливаются по существующим ID, поэтому
    новые ID не конфликтуют со старыми.
  - Пользователи/теги/клиенты/статусы из задач автоматически
    добавляются в справочники при создании/редактировании.
  - Выпадающие списки поддерживают фильтрацию при вводе.
  - Все операции по каталогам (бэкапы/БД) доступны в «Настройки» →
    «Общее» с кнопками «Открыть в проводнике».
